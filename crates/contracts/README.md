# GridForge contracts

Public Phase 0 wire, HTTP and storage contracts.

Nothing in this crate runs. It defines what producers and consumers may rely on.

## Envelope v1

Source: [`proto/gridforge/v1/envelope.proto`](proto/gridforge/v1/envelope.proto).

| Field | Type | Rule |
|---|---|---|
| `schema_ver` | `uint32` | Must be `1` in Phase 0. |
| `org_id` | `string` | UUID string; must match the configured organization. |
| `device_id` | `string` | 1 to 128 characters, `[A-Za-z0-9._:-]`. |
| `boot_count` | `int64` | `>= 0`. |
| `seq` | `int64` | `>= 0`. |
| `device_ts` | `google.protobuf.Timestamp` | Device clock; untrusted. Stored as sent. |
| `payload` | `bytes` | Opaque bytes, at most 32 KiB. |
| `payload_type` | `string` | Non-empty MIME type. |

The server assigns the database `id` (UUIDv7), `ingest_ts` and `persisted_ts`. Producers do not send them.

Phase 0 accepts exactly `schema_ver = 1`. An unknown future schema returns `422`; it is not silently dropped. Phase 3 adds parked messages and a counter.

`boot_count` and `seq` are validated but not used for uniqueness until Phase 3. Phase 0 has no deduplication, ordering or clock-skew rule.

## HTTP API

Source: [`openapi/openapi.yaml`](openapi/openapi.yaml).

| Method | Path | Success |
|---|---|---|
| `GET` | `/` | `200 text/html` dashboard. |
| `POST` | `/events/test` | `303` to `/`, or `202` JSON `{ "id": "<uuid>" }`. |
| `POST` | `/ingest` | `202` JSON `{ "id": "<uuid>" }`. |
| `GET` | `/healthz` | `200 text/plain` `ok`; never checks the database. |
| `GET` | `/readyz` | `200` ready; `503` when the database is down or draining. |
| `GET` | `/metrics` | `200 text/plain` Prometheus exposition. |

Every response carries `x-request-id`. Errors use `application/problem+json` with `type`, `title`, `status`, `detail`, `instance` and `request_id`.

`POST /ingest` accepts only `application/x-protobuf`. The HTTP body limit is 64 KiB; the Envelope payload limit is 32 KiB. JSON ingest is rejected with `415`.

The test endpoint is a thin producer. It builds a valid Envelope with `device_id = "test-button"` and uses the same `EventSink` as device ingest. It never writes to the database directly.

Phase 0 has no authentication. The service is cluster-internal and is not exposed to the internet.

## Event state machine

```text
Accepted -> Enqueued -> Persisting -> Persisted
                |             |
                |             +-> Retry -> Persisting
                |             +-> Failed
                +-> Dropped
```

- **Accepted**: envelope decoded and validated; server id and `ingest_ts` assigned.
- **Enqueued**: `try_send` succeeded on the bounded in-process channel.
- **Persisting**: worker started the single database insert.
- **Persisted**: insert committed; the event is immutable.
- **Retry**: bounded retry after a database failure.
- **Failed**: retries exhausted; the event will not be persisted.
- **Dropped**: channel full or closed before enqueue.

Illegal transitions include `Accepted -> Persisted` without enqueueing, `Persisted -> Retry`, and any transition that inserts an event twice.

One insert is attempted per event. No transaction spans the channel. The channel is not durable; Phase 0 records drops in `events_dropped_total`.

## Process state machine

```text
Starting -> Ready -> Draining -> Stopped
```

On shutdown, in order:

1. Stop accepting new requests.
2. `/readyz` returns `503` while `/healthz` stays `200`.
3. Close the channel sender.
4. Drain queued events for at most 5 seconds.
5. Close the database pool and exit.

Illegal transitions include `Starting -> Draining` without becoming ready, and `Stopped -> Ready`.

## Storage mapping

The Phase 0 migration creates one `events` table. The mapping from Envelope to row is one-to-one except the three server-owned columns.

- `id` is generated by the application as UUIDv7.
- `device_ts` is stored exactly as received.
- `ingest_ts` is assigned at acceptance.
- `persisted_ts` is the insert time and is the table's creation timestamp.
- `payload` is `bytea`; `payload_bytes` is `octet_length(payload)` and is enforced by a check constraint.
- There is no `orgs` table or foreign key in Phase 0. `org_id` is still on every row.
- There is no unique constraint, soft delete, history table or retention policy in Phase 0.

The index is `events_recent_idx` on `(org_id, ingest_ts DESC, id DESC)`.

## Compatibility

- Envelope v1 changes are additive. Removing or renumbering fields is breaking.
- The first proto commit becomes the `buf breaking` baseline after it merges.
- `buf lint` uses the `STANDARD` rules.
- The OpenAPI document is hand-written; there is no generated server or client.
- The dashboard is server-rendered. There is no JSON API for reading events in Phase 0.
